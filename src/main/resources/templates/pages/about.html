Spring Boot Application Template/Starter-Project

Purpose

The only thing better than a Maven archetype is a repo you can fork with everything already setup to speed up the creation of new Spring Boot based Web applications, just fork-and-code.

This repository contains a recipe/scaffolding for bootstrapping a Web Application with the features & technology stack listed below. Delete the sample code (or keep it) and add your own, you’re good to go.

The full documentation lives in the documents folder of the repository.

Features

  • Spring Boot 4.1 on Java 21, Spring Security 7, Spring Data JPA, Thymeleaf with Bootstrap 5
  • Web UI with form login, remember-me, CSRF protection, dark mode and internationalization (English, Spanish)
  • REST API secured with RS256 signed JWT access tokens and rotating, single-use refresh tokens, or HTTP Basic
  • Sign-up with e-mail verification, login throttling per client IP
  • Role and permission based access control, RBAC user management API
  • API rate limiting with Bucket4j, HATEOAS links, RFC 9457 problem details for errors
  • Flyway migrations for H2 and MySQL, JPA auditing, caching
  • OpenAPI 3 / Swagger UI, Actuator with Prometheus metrics
  • Docker image and Docker Compose with MySQL, GitHub Actions CI, integration tests, JaCoCo coverage

Getting Started

Requirements: Java 21. Maven is provided through the wrapper.

./mvnw spring-boot:run        # http://localhost:8080 , in-memory H2 database (default "test" profile)
./mvnw verify                 # tests + coverage report in target/site/jacoco/index.html

The dev, qa, staging and production profiles use MySQL. Everything environment specific is read from environment variables or a git-ignored .env file (see .env.example):

VariablePurpose
SPRING_PROFILES_ACTIVEtest (default, H2), dev, qa, staging, production
DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME, DB_PASSWORDMySQL connection
JWT_KEY_STORE, JWT_KEY_STORE_PASSWORD, JWT_KEY_ALIASRSA key used to sign access tokens. Required in production: without it a temporary key is generated at startup and tokens stop working on restart
REMEMBER_ME_KEYSecret for remember-me cookies, random per start when unset
MAIL_HOST, MAIL_PORT, MAIL_USERNAME, MAIL_PASSWORDSMTP server for sign-up verification e-mails
BASE_URLPublic URL used in verification links

Create a JWT signing key store (keep it out of the repository):

keytool -genkeypair -alias sbat -keyalg RSA -keysize 2048 -validity 3650 \
        -storetype PKCS12 -keystore secrets/jwt.p12 -dname "CN=sbat"

Security

Web UIREST API (/api/**, /rbac/**, /actuator/**)
LoginForm login at /sbat/login, optional remember-mePOST /api/v1/auth/login returns a JWT, or HTTP Basic
StateHTTP session, 10 minute timeoutStateless, Authorization: Bearer <token> on every request
CSRF protectionOnNot needed (header based authentication)

After 5 failed logins from the same IP address, that address is blocked for 15 minutes. Roles and permissions are read from the database on every request, also for token authenticated requests.

Using the API

# 1. Login: returns a short lived access token and a single use refresh token
curl -s -X POST localhost:8080/api/v1/auth/login -H 'Content-Type: application/json' \
     -d '{"username":"Admin1","password":"password"}'

# 2. Call the API with the access token (person endpoints also need an X-api-key header)
curl -s localhost:8080/api/v1/person -H "Authorization: Bearer $ACCESS_TOKEN" -H 'X-api-key: FX001-demo'

# 3. Exchange the refresh token for a new pair; the old refresh token stops working
curl -s -X POST localhost:8080/api/v1/auth/refresh/token -H 'Content-Type: application/json' \
     -d '{"token":"'"$REFRESH_TOKEN"'"}'

API Rate Limiting

Requests to /api/v1/person/** need an X-api-key header. The key's prefix selects the tier; buckets refill every 20 minutes. Responses carry X-Rate-Limit-Remaining; an empty bucket gives 429 Too Many Requests with X-Rate-Limit-Retry-After-Seconds.

TierRequests per 20 minutesAPI key prefix
FREE25any other value
BASIC50BX001-
PROFESSIONAL75PX001-

Internationalization (i18n)

Texts are stored in src/main/resources/i18n (messages.properties, messages_es.properties) instead of the templates. Switch the language with the menu in the navigation bar or by adding ?lang=es to a URL. Refer to io.github.anantharajuc.sbat.core_backend.infra.config.I18Nconfiguration.
